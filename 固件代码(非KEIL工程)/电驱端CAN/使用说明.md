# 电驱端 CAN 三轴角度通信

对应用户说明的板1/板5电驱电路。STM32F103C8T6标准库，PA11=CAN_RX、PA12=CAN_TX，500kbit/s。所提供工程中PCB5的U8焊盘32/33分别接CAN_RX/CAN_TX，与代码一致。当前只编写电驱端，主控程序之后再做。

## 加入工程

添加can_pitch.c/.h及标准库stm32f10x_can.c、stm32f10x_gpio.c、stm32f10x_rcc.c、misc.c，已有文件不重复添加。

main.c包含can_pitch.h，删除原来的the_angles、Its_Time_to_PID定义，本模块已定义这两个volatile变量。USB_LP_CAN1_RX0_IRQHandler只能保留一份实现；该向量与USB共享，本例不同时使用USB。原定时器不再置PID标志。

不重设系统时钟。PCLK1=36MHz时，36MHz / 6 / (1+9+2) = 500kbit/s，采样点83.3%；CAN使用PCLK1，没有定时器的APB倍频规则。

完成电机标定和PID初始化后调用一次，返回0时应停机：

```c
if (!CANPitch_Init()) {
    SVPWM_Stop(0);
    SVPWM_Stop(1);
    while (1) { }
}
```

## 接收流程

经典CAN每帧最多8字节，三个float共12字节。本版按0.01度编码为三个16位有符号整数，共6字节，一帧完整传输。

CAN硬件完成帧接收与校验后触发FIFO0中断；软件检查标准数据帧、接收ID、DLC=6，再依次更新：

```c
the_angles[0] = pitch; // 度
the_angles[1] = roll;  // 度
the_angles[2] = yaw;   // 度
Its_Time_to_PID = 1;   // 三个角度全部更新后置位
```

PID与编码器读取仍在主循环，SVPWM_Update在PID条件判断外持续调用。仅使用Pitch时可以沿用：

```c
if (Its_Time_to_PID) {
    Its_Time_to_PID = 0;
    angle_pitch = the_angles[0];
    /* 读取轮速、计算PID、更新方向与幅值。 */
}
```

如果沿用Balance_ReadFeedback，其中的俯仰角接口可这样对接，在收到角度后的PID处理路径中调用：

```c
int Balance_ReadPitch(float *pitch)
{
    *pitch = the_angles[0];
    return 1;
}
```

如果一次使用或回传三个角度，应在很短的临界区内复制，避免读到一半时被新报文中断打断。volatile不保证整个数组一起读取：

```c
float angles[3];
uint8_t ready;
uint32_t saved_irq = __get_PRIMASK();
__disable_irq();
ready = Its_Time_to_PID;
if (ready) {
    Its_Time_to_PID = 0;
    angles[0] = the_angles[0];
    angles[1] = the_angles[1];
    angles[2] = the_angles[2];
}
__set_PRIMASK(saved_irq);

if (ready) {
    /* 使用本地angles计算PID或回传；不要在临界区内进行这些操作。 */
}
```

单个标志位表示有新数据，不累计帧数；多帧积压时采用最后收到的数据，不逐帧补算PID。

## 回传三个角度

```c
CANPitch_Send(angles[0], angles[1], angles[2]);
// 示例：CANPitch_Send(12.5f, -3.25f, 90.0f);
```

发送函数现在需要三个参数。返回1表示提交硬件邮箱，不代表主控收到；返回0表示邮箱忙、输入非有限或超范围。不等待发送完成，不自动重发旧帧；下一次需要发送时再发最新角度，不要在while内无限频率发送。

## 后续主控必须遵循的协议

| 项目 | 约定 |
|---|---|
| 主控发、电驱收 | 标准ID 0x101 |
| 电驱发、主控收 | 标准ID 0x102 |
| 帧类型与长度 | 标准数据帧，DLC=6 |
| Data[0]、Data[1] | Pitch，低字节在前 |
| Data[2]、Data[3] | Roll，低字节在前 |
| Data[4]、Data[5] | Yaw，低字节在前 |
| 每轴编码 | 16位有符号补码，四舍五入(angle_deg × 100) |
| 解码 | 有符号整数 × 0.01，得到单位为度的float |
| 范围、分辨率 | −327.68°～+327.67°；0.01°，量化误差约不超过0.005° |

例如[12.50°, -3.25°, 90.00°]编码为：

```text
E2 04  BB FE  28 23
Pitch  Roll   Yaw
```

常见欧拉角−180°～+180°可直接表示。若Yaw采用0°～360°，发送前将大于180°的Yaw减360°，例如350°发送为−10°，避免超过编码范围。本模块不自动改变角度的表示范围。

旧版DLC=4的单个float报文不再接受，后续主控必须按本版6字节协议发送。CAN硬件完成CRC校验，不另加串口式帧头、帧尾或软件CRC。

## 调度与连线

PID已把时间并入增益，后续主控应按调参时的固定周期发送，例如5ms。总线延迟、丢帧和主循环耗时会影响实际计算间隔。通信中断后上次电机输出可能继续保留，整车程序需根据已有毫秒时基判断数据超时并停机；本模块不占用定时器，也不实现整车停机策略。

两板均需CAN收发器；CANH接CANH、CANL接CANL，按收发器要求共地，总线两个物理末端各120Ω。PA11/PA12是MCU逻辑侧接口，不是CANH/CANL。
