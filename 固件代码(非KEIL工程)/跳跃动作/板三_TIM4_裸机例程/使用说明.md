# 板三：TIM4直接计数的裸机跳跃例程

适用于STM32F103C8T6标准库，不使用FreeRTOS或HAL。原jump.c/.h保持不变。本目录用TIM4为每次跳跃单独计时，主循环读取CNT；不使用TIM4中断。

## 计时方式

在TIM4输入时钟72MHz时：

```c
PSC = 7200 - 1;  // 72MHz / 7200 = 10kHz，每个计数0.1ms
ARR = 65535;    // CNT从0到65535，共65536个计数
```

一轮为65536×0.1ms=6553.6ms=6.5536s。CNT=65535时，经过6553.5ms；再经过0.1ms才溢出。

代码通过RCC_GetClocksFreq读取启动代码已经设置的时钟，自动计算PSC；72MHz时就是7199。APB1未分频时TIM4=PCLK1，分频时TIM4=2×PCLK1。要求时钟能整分频到10kHz，且PSC不超16位，否则Init返回0。不调用SystemInit，不重新配置系统时钟。

读取时间为整数毫秒：

```c
now_ms = TIM_GetCounter(TIM4) / 10u;
```

例如CNT=12345表示1234.5ms，传给原jump函数的是1234ms。硬件分辨率0.1ms，原jump接口分辨率仍为1ms。

## 一次动作的顺序

```text
上电初始化TIM4 → 保持停止，CNT=0
收到起跳命令 → Jump_Start(0)
                         ↓ 成功
                JumpTick_Start()，从0开始计时
                         ↓
主循环读取毫秒数 → Jump_Update(now_ms)
                         ↓ 完成/取消/错误
                JumpTick_Stop()，停止并清零
```

Jump_Start内部的初始化计算、首次IIC检查不计入本次时间；它下发最低目标并返回成功后才启动计时。重复START在动作运行时被忽略，不会清零正在运行的计数器。

Jump_Update仍在主循环执行；内部按JUMP_SAMPLE_MS（目前5ms）采样和更新缓冲轨迹。不补发遗漏时刻。定时器与MPU采样不是硬件同步。主循环应避免长延时和阻塞打印，尽量每1～5ms获得一次调用机会。

## 停止与清零

JumpTick_Stop执行：

```c
TIM_Cmd(TIM4, DISABLE);
TIM_GenerateEvent(TIM4, TIM_EventSource_Update);
TIM_ClearFlag(TIM4, TIM_FLAG_Update);
```

TIM_GenerateEvent写EGR的UG位。当前是向上计数模式，因此CNT归零、预分频内部计数归零，并装载PSC/ARR配置；不是把ARR=65535复制到CNT。UG同时会置更新标志，最后一行将其清除，避免下次误报溢出。单独TIM_SetCounter(TIM4, 0)不能完成预分频内部计数的复位。

本例不需要TIM4_IRQHandler，不使能TIM4中断，也不需要软件累加毫秒数。若工程保留上一版中断函数，可以移除旧计时内容。

## 6.5536秒边界

大多数设定下单次动作可以在这一时间范围内结束，但原跳跃模块的缓冲阶段可能因为速度限制或调用延迟而延长，所以不把“绝对不会超时”当成前提。

JumpTick_Millis读取CNT后检查更新标志UIF。一旦自然溢出，就返回JUMP_TICK_EXPIRED（UINT32_MAX）；主循环取消后续动作、停表清零并显示JUMP_ERROR，不把回绕后的CNT当作新时间。未开启中断时，硬件仍然会置UIF。读取过程中刚好溢出也会被检查到。

这是本次计时范围的保护，不会改变jump.c里的JUMP_TIMEOUT_MS。若以后确实需要超过6.5536s的动作，应扩展计时方案。

## 加入工程

- jump_tick.c/.h：TIM4初始化、启动、停止及读取。
- main_example.c：完整主循环示例；已有main时合并，不要重复定义main。
- 沿用原jump.c、leg_ik.c、servo.c、mpu9250_simple.c及对应头文件。
- 标准库使用stm32f10x_rcc.c、stm32f10x_gpio.c、stm32f10x_tim.c及F103中容量启动文件；定义STM32F10X_MD、USE_STDPERIPH_DRIVER。

TIM3继续输出PA6、PA7、PB0、PB1四路舵机PWM。TIM4只作内部计数，不配置通道或GPIO，所以不占用PB6～PB9。已提供的板三代码中未发现其他TIM4占用，实际整合工程仍需保证TIM4独占。板一的TIM4属于另一块MCU。

## 接入原有驱动

main_example.c顶部宏保留为：

```c
#define JUMP_EXAMPLE_PORT_INIT() Board_JumpPortInit()
```

在Board_JumpPortInit中调用你已有的IIC GPIO与延时初始化，也可将宏直接替换为已有函数。原工程已完成这些初始化时可省略。这里不猜测MPU接线，不重新配置系统时钟。

本版TIM4在空闲、初始化和结束后都会停止，不能再作为Delay_ms、Delay_us或其他控制任务的系统时基。延时函数使用你已有的独立实现，也不能占用TIM3/TIM4。

MPU驱动需要SDA、SCK、SDA_Read、Delay_ms、Delay_us。当前IIC_Delay使用Delay_us(3)，但源文件尚缺Delay_us声明；应让该源文件包含你已有的延时头文件，或在工程里预包含该头文件。声明必须与真实实现一致。本次未修改该驱动。不要退回1ms的软件IIC位延时，否则无法支持5ms采样。

jump.h中仍需填写实际杆长、四路舵机零位/方向/限位和LOW、MID、BUFFER、HIGH等参数，满足LOW < BUFFER < MID < HIGH。未填写时Start仍按原逻辑返回错误。

## 触发和观察

```c
extern volatile uint8_t g_jump_command;
g_jump_command = 1;  // 请求跳一次
// 或：
g_jump_command = 2;  // 取消后续动作，保持已发出的舵机目标
```

按键按下沿或一条新CAN命令触发一次赋值。主循环自动取走并清零；运行中收到START直接忽略，不排队。不要在每轮循环中反复写1。命令变量只保存最近一条，主循环用极短临界区避免读取/清除时丢失新命令；Jump函数和IIC仍全部在主循环执行。

| 变量 | 含义 |
|---|---|
| g_jump_ready | 1表示驱动初始化成功，不代表机械标定已验证 |
| g_jump_command | 写1起跳、写2取消；上电默认为0，不自动跳跃 |
| g_jump_state | 0空闲、1运行、2原模块报告动作结束、-1错误 |

正常结束后g_jump_state保持结果，TIM4已停表清零；新START可以开始下一次动作。JUMP_LANDED仍只是原模块的落地估计及目标轨迹结果，不保证真实舵机到位。取消和错误不会切断舵机电源。其他调腿程序不能同时覆盖四路舵机目标。
