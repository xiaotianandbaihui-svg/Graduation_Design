# MPU9250 精简版：只公开 5 个驱动函数

只把 `mpu9250_simple.c` 和 `mpu9250_simple.h` 加入单片机工程，不要同时加入旧版驱动。
软件 IIC 的完整实现都在 `.c` 文件中，用 `static` 修饰；主程序不用直接调用。
没有设备结构体，没有独立的磁力计初始化接口，也没有要求你提供微秒延时。

## 1. 你提供的底层功能

```c
void SDA(uint8_t level);       // 0：拉低 SDA；1：释放 SDA
void SCK(uint8_t level);       // 0：拉低 SCL；1：释放 SCL
uint8_t SDA_Read(void);        // 读 SDA 的实际电平，返回 0 或 1
void Delay_ms(uint32_t ms);    // 至少等待 ms 毫秒，使用你已有的延时
```

`SCK()` 就是你给 IIC 时钟线起的函数名，这根线在 IIC 中叫 SCL。
只有两个输出函数无法读取从机的数据和 ACK，所以 `SDA_Read()` 是必需的。
如果你现有的延时函数叫 `Delayms()`，把 `.c` 里的 `Delay_ms` 统一改成它即可，声明的参数类型也要与原函数一致。
如果 SDA/SCK 是宏，则包含你的 GPIO 头文件，去掉本文件顶部对应的 `extern` 函数声明。

- GPIO 在调用初始化之前配好，SDA/SCL 使用开漏输出，初始均释放为高。
- SDA/SCL 需要上拉到兼容双方的逻辑电源；STM32 与本芯片通常使用 3.3V，可先用 4.7kΩ。模块已有合适上拉时不用重复加。
- STM32 与模块共地。MPU9250 的 nCS 必须为高以使用 IIC；模块若已接好则不用另接。
- `MPU_ADDR=0x68` 对应 AD0 为低；AD0 为高改成 `0x69`。这里全部使用 7 位地址。
- 此精简实现适用于一台主机访问 MPU9250/AK8963；没有 SCL 回读、时钟拉伸、多主机仲裁或卡死总线恢复。它会检查 SDA 总线状态和每个发送字节的 ACK。

## 2. 主程序只调用这 5 个函数

```c
uint8_t MPU9250_Init(void);
uint8_t MPU9250_ReadAccel(int16_t xyz[3]);
uint8_t MPU9250_ReadGyro(int16_t xyz[3]);
uint8_t MPU9250_ReadMag(int16_t xyz[3]);
uint8_t MPU9250_CalcAngles(const int16_t accel[3], const int16_t gyro[3],
                           const int16_t mag[3], float dt_s, float angle_deg[3]);
```

都返回 `1` 表示成功、`0` 表示失败或暂无有效数据；失败时传入的输出数组保持原值。
角度函数不读硬件，直接用你已经读出的三个数组计算。

| 函数 | 输出/行为 |
|---|---|
| `MPU9250_Init` | 检查两颗传感器的 ID，复位并配置加速度计、陀螺仪和内部 AK8963 磁力计，同时清除角度滤波状态 |
| `MPU9250_ReadAccel` | 原始加速度 `int16_t[3]`，顺序为芯片 X/Y/Z；除以 16384.0 得到 g |
| `MPU9250_ReadGyro` | 原始角速度 `int16_t[3]`，顺序为芯片 X/Y/Z；除以 16.4 得到度/秒 |
| `MPU9250_ReadMag` | 原始磁场 `int16_t[3]`，顺序为 AK8963 X/Y/Z；未校准、未换单位、未变换坐标 |
| `MPU9250_CalcAngles` | `angle_deg[0]` 横滚、`[1]` 俯仰、`[2]` 航向，单位都是度；内部应用磁场出厂系数、坐标转换和简单互补滤波 |

加速度/角速度读取函数获取当前寄存器值，不额外轮询数据就绪标志；调用过快可能读到重复样本。
磁力计读取会检查 ST1，连续读完 XYZ 和 ST2，并检查磁场溢出；尚无新数据或溢出时返回 0。
三个读取函数分别访问硬件，不保证是同一时刻的样本。

## 3. 初始化就是逐条写寄存器

实现采用 `WriteReg(器件地址, 寄存器地址, 配置值)`，没有额外配置框架。
每一条写入都检查从机 ACK，任一步失败，初始化立即返回 0。

| 步骤 | 寄存器和值 | 含义 |
|---|---|---|
| 1 | MPU `WHO_AM_I` 应为 `0x71` | 确认是真正的 MPU9250；不把 MPU6500 当作九轴芯片 |
| 2 | `PWR_MGMT_1=0x80`，等待 100ms，再写 `0x01`，等待 100ms | 复位、唤醒、选择时钟 |
| 3 | `PWR_MGMT_2=0x00`，`USER_CTRL=0x00`，`FIFO_EN=0x00` | 所有轴工作，不启用内部 IIC 主机和 FIFO |
| 4 | `CONFIG=0x03`，`GYRO_CONFIG=0x18` | 陀螺仪低通约 41Hz，量程 ±2000 度/秒 |
| 5 | `ACCEL_CONFIG=0x00`，`ACCEL_CONFIG2=0x03` | 加速度量程 ±2g，低通约 40Hz；不沿用旧例程向保留位写 1 的 `0x01` |
| 6 | `SMPLRT_DIV=0x04` | 当前设置下，芯片内部数据率 1000/(1+4)=200Hz |
| 7 | `INT_ENABLE=0x00`，`INT_PIN_CFG=0x02` | 不使用中断引脚，打开磁力计旁路 |
| 8 | AK `WIA` 应为 `0x48`，`CNTL2=0x01` | 确认并复位 AK8963 |
| 9 | AK `CNTL1` 依次写 `0x00`、`0x0F`，读取 `ASAX/Y/Z` | 读取出厂灵敏度系数；每次模式切换后等待 1ms |
| 10 | AK `CNTL1` 依次写 `0x00`、`0x16` | 进入 16 位、100Hz 连续测量模式；最终等待 100ms |

依据是本地厂商资料里的 `RM-MPU-9250A-00.pdf`（寄存器手册，MPU 配置以及 AK8963 寄存器章节）。
磁力计到加速度计的坐标变换 `(My, Mx, -Mz)` 依据 `PS-MPU-9250A-01.pdf` 第 38 页的两张轴向图。
这两份手册已保存在工程的 `work/mpu9250_sources` 目录。
100ms 等待、量程/滤波档位、互补滤波参数是本示例选择，不是唯一配置。

## 4. 最简调用示例

下面假设 `system_ms` 是由你现有的系统时基每 1ms 加 1 的计数器。
也可以用工程已有的毫秒时间戳，例如 HAL 工程的 `HAL_GetTick()`。
时间戳来自单片机，不是传感器额外接口；关键是测量真实间隔，不写死 0.001 秒。

```c
#include "mpu9250_simple.h"
#include <stddef.h>

extern volatile uint32_t system_ms; /* 由你现有的 1ms 中断维护 */

int16_t accel[3], gyro[3], mag[3];
float angle[3];
uint32_t now_ms, last_ms = 0;
uint8_t first = 1;
uint8_t mag_ok;

/* 先完成你已有的 GPIO 和时基初始化，然后： */
if (!MPU9250_Init()) {
    /* 通信或芯片 ID 不正确；在这里报错，不继续使用角度。 */
    while (1) { }
}

while (1) {
    if (!MPU9250_ReadAccel(accel)) continue;
    if (!MPU9250_ReadGyro(gyro)) continue;
    mag_ok = MPU9250_ReadMag(mag);
    now_ms = system_ms;

    if (MPU9250_CalcAngles(accel, gyro, mag_ok ? mag : NULL,
                          first ? 0.0f : (uint32_t)(now_ms-last_ms)*0.001f,
                          angle)) {
        last_ms = now_ms;
        first = 0;
        /* angle[0]：横滚；angle[1]：俯仰；angle[2]：航向 */
    }
}
```

无新磁场数据时传 `NULL`，滤波已建立后会暂时仅用陀螺仪更新航向；不要把旧磁场反复当作新数据。
初始化后的首次角度计算要求有有效磁场，并且加速度模长接近 1g，因而最好近似静止。

## 5. 1ms 延时的实际速度

`IIC_Delay()` 就是一句 `Delay_ms(1)`。一个数据位低、高各等待 1ms，理想位时钟约 **500Hz**，不是 500kHz。

| 操作 | 仅计算代码中延时的时间 |
|---|---:|
| 读取一次三轴加速度 | 171ms |
| 读取一次三轴角速度 | 171ms |
| 磁力计就绪时读取一次三轴磁场（含状态查询） | 270ms |
| 三组都读一遍 | **612ms，最多约 1.63 组/秒** |
| 完整初始化 | 约 1.7 秒 |

GPIO 调用、中断、实际毫秒延时实现会使耗时进一步增加。
内部 200Hz/100Hz 是芯片生成数据的速度，不是当前主机取数速度；此配置会漏掉许多中间样本。
这版适合先读通、观察静止或缓慢变化的数据，**不适合当前时序下的轮足平衡闭环**。
等需要控制电机时，再把私有 `IIC_Delay()` 改为经验证的微秒延时，或更换硬件 IIC；上面 5 个接口不用因此改变。

## 6. 三个角度的含义和边界

- 以芯片加速度/陀螺仪坐标为准；板子安装方向与车体方向不一致时，还需要处理安装变换。
- 横滚约为 −180°～180°；此简易欧拉角滤波限制 **俯仰绝对值小于 80°**，超出返回 0。
- 航向为 0°～360°，磁北为零，绕芯片 +Z 的右手方向为正；未补磁偏角，不是地理真北航向，也不是默认按指南针顺时针增加。
- 陀螺仪用于短时积分，加速度用于修正横滚/俯仰，倾斜补偿后的磁场用于修正航向。计算使用真实 `dt_s`。
- 程序自动读出的 AK8963 灵敏度系数不等于整机标定。`gyro_bias`、`mag_bias`、`mag_scale` 默认没有标定；获得标定值后在 `.c` 顶部填入。
- 加速度模长检查只是简单筛选，不能排除所有运动加速度影响。电机、永磁体、供电电流也会干扰磁场。当前实现不声称满足快速运动时的高精度姿态估计。
- 这份驱动只管理一个模块，内部保存姿态状态。不要同时从主循环和中断调用。
