# STM32F103C8T6：TLE5012B 读取与 BDS3620 六步换相

本示例使用 **STM32F10x 标准外设库（SPL）**，不依赖 HAL。对象为 BDS3620、TLE5012B 和 MODE 接地的 DRV8323H。默认只读取电机1的角度，不自动标定、不自动转动。

代码支持板1的两路电机。引脚依据此前检查得到的 **2026-09-29 板1网络表**，本次没有重新解析最新版 EDA 工程；接入前应对照实际 PCB。电机按你提供的参数设置为 **14 极、7 对极**。

## 2. 实际引脚

电机编号 `id=0` 对应电机1，`id=1` 对应电机2。

| 功能 | 电机1 | 电机2 |
|---|---|---|
| INHA | PA1 / TIM2_CH2 | PB7 / TIM4_CH2 |
| INHB | PA2 / TIM2_CH3 | PB8 / TIM4_CH3 |
| INHC | PA3 / TIM2_CH4 | PB9 / TIM4_CH4 |
| INLA | PB12 | PB15 |
| INLB | PB13 | PB3 |
| INLC | PB14 | PA15 |
| nFAULT | PA8 / EXTI8 | PB5 / EXTI5 |
| ENABLE | PB0，两片驱动器共用 | PB0，同左 |
| 编码器 CSQ | PA4 | PB1 |
| 编码器 SCK | PA5 / SPI1_SCK，共用 | 同左 |
| 编码器 MISO | PA6 / SPI1_MISO，共用 | 同左 |
| 编码器 MOSI | PA7 / SPI1_MOSI，共用 | 同左 |

**不使用 PA0。** 电机2占用 JTAG 的 PB3、PA15，初始化中关闭 JTAG，保留 PA13/PA14 的 SWD。若后续代码再次调用 GPIO 重映射函数，注意不要恢复 JTAG 占用这两个引脚。

虽然名称叫“6PWM模式”，这份六步算法只需每个电机 **3路定时器PWM + 3路GPIO**。INHx接PWM，INLx由GPIO控制。MODE必须为接地的6PWM模式，不能按3PWM或1PWM模式接线。

ENABLE 是共用的，因此初始化始终关闭两路的全部门极输入。任一路驱动器故障都会拉低共享 ENABLE、停止两路；即使只启用编码器1，也监控两片驱动器的 nFAULT。

## 3. TLE5012B 的“SPI”接法必须确认

TLE5012B 芯片本身使用 **SSC双向DATA**。本例用STM32的SPI1产生时钟与16位收发，协议是：

- Mode 1：SCK空闲低，上升沿更新数据、下降沿采样。
- 16位、MSB先行；72MHz外设时钟除16，SCK为4.5MHz。
- 发送 `0x8021`，随后读取16位角度和16位安全字。
- 发完命令后把PA7改为浮空输入，释放发送端；从PA6接收。
- 采用器件默认的推挽SSC模式。若模块被另行配置为开漏，不能直接沿用4.5MHz。

你的成品板虽然引出了MOSI、MISO，但目前没有确认它内部拆分DATA的方法。以下是芯片DATA与MCU分线连接的原理示意，**不是已经核实的成品板内部电路**：

```text
PA7 / MOSI ── 串联电阻 ──┐
                         ├── TLE5012B DATA
PA6 / MISO ───────────────┘
PA5 / SCK ────────────────── SCK
PA4或PB1 ─────────────────── CSQ
GND ──────────────────────── GND
```

手册图3-6给出DATA串联电阻470Ω的示例。若模块已有对应电路，按模块接口接线，不要盲目再短接MOSI/MISO。两只模块共享总线还要求：未选中的模块必须释放MISO。

**5V模块供电与3.3V逻辑兼容是两个问题。** 模块按厂商要求供电，但应确认其MISO到PA6的输出电平和MOSI/SCK/CS的输入门限适合3.3V MCU；不能仅凭“模块用5V”就假设通信脚可以直连。电阻限流不能代替必要的电平转换。这是目前尚待模块电路或实测确认的接入条件。

初始化不会改写编码器角度零位、EEPROM、磁场补偿或接口配置：先等待启动，再读STAT清除上电的历史状态，然后要求一次角度读取通过CRC和全部状态检查。运行中出现新的复位、无效角度、系统错误或通信错误即锁存停机。

## 4. 加入你的标准库工程

1. 选择 STM32F103C8T6，定义 `STM32F10X_MD`、`USE_STDPERIPH_DRIVER`。
2. 加入 `motor.c`、`tle5012b.c`、`motor_port_stm32f103.c`；加入本目录的头文件搜索路径。
3. 标准库源文件至少包含 `stm32f10x_rcc.c`、`stm32f10x_gpio.c`、`stm32f10x_spi.c`、`stm32f10x_tim.c`、`stm32f10x_exti.c`、`misc.c`。
4. 保留工程自己的 CMSIS、`system_stm32f10x.c` 和中容量启动文件 `startup_stm32f10x_md.s`。
5. 时钟要求 HCLK=72MHz、PCLK1=36MHz、PCLK2=72MHz。本例会核对，不符合则拒绝启用输出。示例按常见8MHz外部晶振配置使用，不在驱动里重设整机时钟。
6. 本例定义了 `EXTI9_5_IRQHandler`、`TIM3_IRQHandler`。如果工程已有同名中断函数，把处理内容合并，不要重复定义。
7. `example_main.c` 与你的原 `main.c` 二选一；测试文件不加入 Keil 工程。

资源占用：SPI1、TIM2的CH2/3/4、TIM4的CH2/3/4、TIM3、EXTI5和EXTI8，以及DWT周期计数器。TIM3每100μs检查更新是否失联。本例不占用SysTick，不调用HAL延时，也不改变其他外设的时钟配置。

本目录提供的是可加入现有标准库工程的源文件与示例，**没有替换你的工程文件，也没有烧录单片机**。

## 5. 最小用法

先运行默认的 `example_main.c`。`Motor_Init(1)`成功后，在主循环不断调用 `Motor_Update()`，用调试器查看 `encoder_raw`、`encoder_degrees`、`motor_fault`。手动转动轴，角度应在0到360°之间循环。

对外主要操作：

```c
Motor_Init(1);                       /* 电机1；改3则读两只编码器 */
Motor_Calibrate(0, 50, &cal);         /* 电机1，以5%占空比标定，会转动 */
Motor_Run(0, 50);                    /* 正向5% */
Motor_Run(0, -50);                   /* 反向5% */
Motor_Stop(0);                       /* 关闭该路输出，滑行 */
Motor_EmergencyStop();               /* 共享ENABLE拉低，双路锁存停机 */

/* 主循环持续执行，无毫秒级阻塞： */
Motor_Update();
Motor_GetAngle(0, &raw, &degrees);    /* 读取最近成功采集的缓存，不另占SPI */
```

上面只展示接口，实际必须检查返回值，完整流程见 `example_main.c`。`Motor_Init`后没有标定数据时，`Motor_Run`返回 `MOTOR_NOT_CALIBRATED`，不会输出PWM。

`Motor_Init`内部已经调用 `TLE5012B_Init`。若只研究编码器，可看 `TLE5012B_ReadRaw`、`TLE5012B_ReadDegrees` 的实现；电机运行时不要再从别的中断直接调用这些函数争用总线。Motor接口也应由同一个主循环调用；硬件故障和超时中断独立负责切断输出。

返回角度为机械角：`degrees = raw × 360 / 32768`，`raw`范围0～32767，角度范围 `[0,360)`。不是无限累计角度，也不是电角度。

## 6. 标定到底做了什么

`Motor_Calibrate(0, 50, &cal)` 是一次约2.4秒的阻塞标定，期间持续校验传感器和驱动故障：

1. 以矢量0（A+、B−、C悬空）保持600ms，让转子对齐。
2. 依次保持矢量1、2、3、4、5、0，每个300ms，走一圈电角度。
3. 检查各步转角方向一致、转角接近 `360/(7×6)=8.57°` 机械角，识别编码器方向。
4. 每次取最后20ms的圆周平均，并检查转子是否基本静止。
5. 返回最终矢量0的角度 `zero_raw`、方向 `encoder_sign` 和极对数7，然后关闭输出。

轴必须能自由转动，另一只电机须停止；首次用限流电源、空载验证。**5%只是起始示例，不保证任何固定电流，也不保证一定足以完成对齐。** 电流或振动不合适时应停机检查，不能反复自动增加占空比。标定失败会锁存故障，不会拿失败结果继续换相。

标定得到的关系是：

```text
电角度 = wrap_360(编码器方向 × 7 × (机械角 − 对齐机械角))
```

这份程序把对齐状态定义成电角度零点；运行时再选相对转子约正/负90°、最接近的60°电压矢量。因此不是“减掉零位后直接除60°就用同一个表”。那样在对齐位置可能没有起动转矩。

该方法是基于转子位置的六步电压驱动，实际电流会受绕组电阻、电感、反电动势和负载影响。它不等于FOC中的精确90°电流控制。

### 标定保存

标定成功会立即在RAM中生效，但断电会丢失。下一次上电可以读取你保存的数据，再调用：

```c
MotorCalibration saved = {0};       /* 必须先从自己的Flash配置中恢复真实数值 */
/* 校验记录的版本、CRC、zero_raw、encoder_sign、pole_pairs后： */
if (Motor_SetCalibration(0, &saved) == MOTOR_OK) {
    /* 等待明确的启动命令，再Motor_Run(0, 50); */
}
```

本例没有自动选择Flash页或擦写，因为尚未拿到你工程的链接布局。F103C8T6按64KB Flash使用，不能随意认为最后一页空闲。需要持久保存时，在链接布局中先保留配置页，再由应用实现保存；电机运行期间不擦写Flash。

不加Flash保存也能调试：每次上电明确调用标定。若磁铁、编码器安装位置或三相接线改变，已有标定失效，应重新标定。每台电机单独保存参数。

## 7. 六步表和PWM输出

这里H、L是 **MCU输出到DRV8323H输入端的逻辑**，不是直接接MOS栅极。

| 矢量 | 电流方向 | INHA | INLA | INHB | INLB | INHC | INLC |
|---:|---|---|---|---|---|---|---|
| 0 | A→B，C悬空 | PWM | 0 | 0 | 1 | 0 | 0 |
| 1 | A→C，B悬空 | PWM | 0 | 0 | 0 | 0 | 1 |
| 2 | B→C，A悬空 | 0 | 0 | PWM | 0 | 0 | 1 |
| 3 | B→A，C悬空 | 0 | 1 | PWM | 0 | 0 | 0 |
| 4 | C→A，B悬空 | 0 | 1 | 0 | 0 | PWM | 0 |
| 5 | C→B，A悬空 | 0 | 0 | 0 | 1 | PWM | 0 |

PWM为20kHz。正负占空比表示两个转矩方向；初次调试默认限幅15%。PWM关闭段靠现有功率级续流，本例没有做同步整流。

换扇区时先把高侧PWM引脚明确拉低、关闭低侧，等待2μs，再建立下一矢量。切换时同时处理CCR预装载，避免上一扇区PWM延迟一个周期才消失。DRV8323H本身的门极互锁/死区仍起作用，代码这段是额外的扇区切换全关间隔。

## 8. 更新周期与保护边界

`Motor_Update()`内部按100μs周期运行，主循环应比这更频繁地调用它。不要在运行期间插入 `Delay_ms(1)`、阻塞串口输出或Flash擦写。微秒计时使用Cortex-M3的DWT，并不要求你已有微秒延时函数。

按6000rpm估算：

```text
6000 / 60 × 7 × 6 = 4200次扇区切换/秒
一个扇区约238μs
```

所以1ms一次读取会跳过多个扇区。10kHz更新只是本例的起始配置，不能据此断言实际电机能够可靠跑到6000rpm；还需测量读取延迟、控制执行时间和高转速换相效果。

调试器可观察 `motor_last_update_us`。运行时一次完整更新达到100μs会停止；有输出但超过500μs没有有效更新，由TIM3每100μs检测并停机。该软件检查需要CPU和中断正常运行，不能代替独立硬件过流保护。

| 情况 | 处理 |
|---|---|
| 编码器总线超时、CRC错误、无效角度或运行中复位 | 关闭两路并锁存故障 |
| 任一DRV8323H的nFAULT下降沿 | 中断拉低共享ENABLE，关闭两路并锁存 |
| 主循环停止更新或一次运行更新超出周期 | 锁存超时并停机 |
| `Motor_Stop(id)` | 仅关闭指定电机，滑行，不是主动刹车 |
| 故障自行消失 | 不自动重启，需确认原因后重新初始化、载入标定并明确启动 |

通过 `Motor_GetFault()` 获取位掩码、`Motor_GetEncoderError(id)` 获取具体编码器错误，定义在头文件中。

**本例没有电流采样闭环，也没有精确11A限流。** nFAULT对应驱动器已配置的故障条件；VDS过流门限取决于硬件设置与MOS导通电阻。参数图中的12A是堵转电流，不能当成已验证的连续工作电流。占空比指令也不能直接等同于LQR要求的力矩指令。

## 10. 验证状态

已用本机Keil的Arm Compiler 6和STM32F1设备包中的真实标准库进行Cortex-M3编译、链接，验证布局为64KB Flash / 20KB RAM。测试过程及结果见 `验证记录.md`，可运行 `tests/validate.ps1` 重现；脚本默认路径对应当前电脑。

这些是编译和软件逻辑验证，**尚未上板验证**。通信电平/模块内部接法、SSC和门极波形、实际电流、标定转动方向与执行时间需要实物确认。
