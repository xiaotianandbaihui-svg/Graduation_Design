# MPU6500：STM32F103C8T6 硬件 SPI2（姿态修正版）

仅需加入 `mpu6500_spi.c` 和 `mpu6500_spi.h`。使用标准外设库，不使用 HAL、RTOS，不重配系统时钟。另提供工程已有的 `Delay_ms()`。

2026-10-15修正：增加启动静止零偏标定；先积分陀螺到当前时刻，再作重力校正；增加有限幅的残余零偏积分修正。`CalcAngles`的时间间隔仍为毫秒、角度仍为度。SPI接线、量程及原始数据接口保持一致。

当前例程采用TIM2中断置标志、主循环读取和解算，已写入`Central_Controller_KEIL/User/main.c`，本目录保留相同内容的`example_tim2_irq.c`。新增`MPU6500_ReadAngles`封装一次读取和解算。不关闭全局中断，初始化标定在开TIM2前完成。

## 接线

| STM32F103C8T6 | MPU6500模块 |
|---|---|
| PB12 | CS |
| PB13 / SPI2_SCK | SCL / SCLK |
| PB14 / SPI2_MISO | AD0 / SDO |
| PB15 / SPI2_MOSI | SDA / SDI |
| GND | GND |
| 3.3V供电 | 按模块的3.3V供电端接入 |

**SPI模式下AD0是数据输出SDO，不能继续接地，也不能悬空。** SDA不再作为双向IIC数据线。INT、EDA/ECL不参与本驱动。逻辑电平为3.3V。

引脚依据此前保存的板三网络记录：PA6/PA7/PB0/PB1用于舵机，PB12～PB15空闲，故选SPI2。当前提供的 `.epro2` 实际只含板五PCB，无法据此确认最新板三；如果板三已修改，请再核对这四脚。原来PB10/PB11的IIC接线必须改接。

## 接口

```c
uint8_t MPU6500_Init(void);
int8_t MPU6500_ReadAngles(uint32_t now_us, float angle_deg[3]);

/* 以下原始接口仍保留，用于自行读取和解算。 */
int8_t MPU6500_ReadRaw(MPU6500_Raw *raw);
uint8_t MPU6500_CalcAngles(const MPU6500_Raw *raw,
                           float dt_ms, float angle_deg[3]);
```

- `Init`：1成功、0失败，核对WHO_AM_I为0x70并读回验证配置，随后采集200个新样本自动标定陀螺零偏。正常约1.4秒，整个过程必须静止但无需水平。明显运动、数据异常或超时返回0；可静止后重试。
- `ReadAngles`：一次完成读取和解算，传入读取开始前的微秒时间戳和输出数组，内部计算相邻新帧的实际调用间隔。1成功、0暂无有效角度、-1通信或参数错误；返回0/-1不改输出，只有返回1才使用本次结果。通信错误后需排查并重新初始化。输出顺序为Pitch、Roll、Yaw，单位度。时间戳允许uint32_t回绕；相邻新帧须小于一个完整回绕周期（约71.6分钟），正常应为几毫秒。
- `ReadRaw`：1读到新帧、0暂无新帧、-1错误；**不能用 `if (ReadRaw(...))` 判断成功，因为-1也是真。** 0/-1不修改输出。传输出错后需重新初始化。
- `CalcAngles`：1成功、0本次无有效角度，失败不修改输出。输出依次为Pitch、Roll、Yaw，单位度。只对成功取得的新帧调用。

温度原始值为有符号整数；本驱动主要用于六轴采样，不据此做温度补偿。

`ReadAngles`和手动`ReadRaw`+`CalcAngles`二选一，不要交替更新同一份姿态历史。`Init`会同时清除封装函数的时间记录；第一帧以重力初始化，不积分此前的时间。暂无新数据时不推进时间记录。初始化之后的调用均放在主循环。

## 速率、量程和滤波

| 项目 | 配置 |
|---|---|
| SPI | 模式3、8位、MSB先发、软件CS |
| 配置/ID读写 | 自动选择不超过1MHz的分频；PCLK1=36MHz时562.5kHz |
| 数据连续读取 | 默认最高18MHz；PCLK1=36MHz时18MHz |
| 数据搬运 | SPI2 RX=DMA1通道4，TX=DMA1通道5；轮询完成，不使用DMA中断 |
| 每次事务 | 1字节地址+15字节状态/数据，一次完整读取六轴和温度 |
| 采样率 | 1kHz，每1ms更新；更快读取也不会得到额外新样本 |
| 加速度 | ±8g，4096 LSB/g；原始值除4096得到g |
| 陀螺仪 | ±2000°/s，16.4 LSB/(°/s)；原始值除16.4得到°/s |
| 内部低通 | 加速度和陀螺均开启，带宽约41Hz |

16字节在18MHz下的纯线路传输时间约7.1µs，完整函数还包括标准库调用和片选延时，不能把7.1µs当成实测函数耗时。DMA避免CPU逐字节收发，但本接口仍同步等待传输结束。

手册允许传感器/中断寄存器高速读取，其余寄存器访问限制在1MHz以内；本代码只在初始化结束后提速，随后高速读取0x3A～0x48。`MPU6500_READ_MAX_HZ`可改为9000000或4500000，用于降低杜邦线、转接板带来的信号完整性风险。18MHz尚未在你的实物上验证。SPI没有ACK和帧CRC，配置读回及超时检测不能保证发现每一处线路误码。

已经使用芯片内部六轴低通，未再叠加软件低通，以减少平衡控制延迟。低通会抑制高频噪声，也有延迟，不是所有毛刺都能消除。修改滤波带宽需同时考虑噪声和控制响应。

独占SPI2及上述两个DMA通道；它们也对应USART1的TX/RX DMA，不能同时用于USART1 DMA。USART1普通中断收发不冲突。不要从中断与主循环并发调用本驱动。工程需加入标准库的GPIO、RCC、SPI、DMA源文件，并启用C99及数学库。

## 调用示例

### 当前使用：TIM2置标志，主循环读取和解算

[example_tim2_irq.c](example_tim2_irq.c)与当前Keil工程main一致；不要再把它作为第二个main加入同一工程。当前工程已经包含TIM标准库源文件，不必增加工程条目。

- 默认`IMU_PERIOD_MS=5u`，即5ms；改为20u即20ms，允许1～50ms。
- TIM2使用1MHz计数，72MHz定时器时钟时PSC=71，5ms时ARR=4999。自动根据当前APB1时钟计算，不重配系统时钟，不占用GPIO。
- TIM2中断只清UIF、累加一次整数时间并将`volatile`标志`flag_to_update`置1；不读SPI、不解算、不打印。
- 主循环先清标志，再调用`MPU6500_ReadAngles(IMU_NowUs(), angle)`。处理期间若新中断置位，下一轮主循环仍可处理。`angle[3]`只由主循环写入，无需关中断复制快照。
- `IMU_NowUs`组合周期累计值和TIM2计数器得到微秒时间戳；跨越更新中断时重读，不关闭中断。只能在主循环、中断正常开启且TIM2已启动时调用。定时器计数为1us，但传感器自身1ms更新，读取时间只是采样时刻的近似。
- TIM2抢占优先级为0，优先级分组沿用Serial_Init设置的分组2。其它代码不能让TIM2中断连续延迟一个周期以上，否则UIF不能记录多次溢出，软件累计时间将丢计数。
- 主循环忙时，多次更新通知会合并成一次，读取最新样本；不会把同一帧补算多次。实际读取间隔不保证严格5ms，封装函数用实测间隔解算；过慢调度仍会丢失期间运动信息。
- 系统上电静止约1.4秒完成标定后才开启TIM2。`imu_result`供调试查看：1新角度、0暂无、-1错误。主循环约每20ms打印一次，减少串口阻塞。

主循环的核心调用：

```c
if (flag_to_update) {
    flag_to_update = 0; /* 清零放在处理前 */
    if (MPU6500_ReadAngles(IMU_NowUs(), angle) == 1) {
        /* angle[0]=Pitch，angle[1]=Roll，angle[2]=Yaw，单位度 */
    }
}
```

串口115200、8N1，输出三列：

```text
Pitch,Roll,Yaw
```

本次保留已使用的姿态算法，没有给角度乘比例系数。实物对照请沿芯片单一X或Y轴分别倾斜，避免把复合倾斜的总角度与某一个欧拉角混淆。

### 保留的主循环20ms例程

直接看同目录的 [example_20ms.c](example_20ms.c)。它是一个独立测试main，不要与原main同时构建。占用TIM2作为0.1ms自由运行时钟，不开中断，不占用GPIO，不修改系统时钟；TIM2不能同时用于其他功能。

该例程按约20ms读取/解算，实际测量间隔放在`imu_dt_ms`，调试器可以直接查看`imu_raw`、`angle`、`imu_dt_ms`、`imu_fault`。计数差允许一次回绕，连续调度间隔须小于6.5536秒；长时间断点暂停后应重启测试。

如果你已有准确的固定20ms调度，基本调用仍然是：

```c
/* main初始化阶段：模块保持静止。 */
if (!MPU6500_Init()) { /* 处理初始化失败 */ }

/* 每20ms一次，且只在读到新帧后解算。 */
if (MPU6500_ReadRaw(&RAW_Data) == 1) {
    if (MPU6500_CalcAngles(&RAW_Data, 20.0f, angle)) {
        /* 此时才使用/发送angle；angle顺序Pitch、Roll、Yaw，单位度。 */
    }
}
```

上面简写仅适合实际相邻有效帧始终相隔20ms。若漏帧或调度延迟，使用例程那样的实测间隔。超过100ms返回0并重置姿态历史，下一帧重新建立倾角，Yaw也从0重新开始，不能当成连续航向。

**Delay_ms(20)后再阻塞打印，不等于20ms周期。** 现有工程的Serial.c配置115200波特率，40字符的8N1输出仅线路传输就需约3.5ms，还未计入格式化耗时。标志位例程限制打印频率，并使用实际读取间隔；独立`example_20ms.c`不打印。若实测周期确实为20ms，传20.0f是正确的。

未使用FIFO，20ms读取只获得最新一帧，不会自动积分期间的20个1kHz样本；快速往返运动/振动仍可能漏采或混叠。原有约41Hz硬件低通也不是针对50Hz采样的充分抗混叠保证。后续平衡控制优先考虑更快采样与解算，CAN仍可20ms发送；此次没有擅自改动硬件滤波配置。

姿态用加速度提供重力方向、陀螺提供旋转增量。首次应静止或近似静止；当加速度模长不在0.8～1.2g时继续积分陀螺及已估计的零偏补偿，暂停重力校正与积分项学习。这只是有效性筛选，不能完全排除运动加速度的干扰。

重力校正`KP=4.0`，离散比例`1-exp(-KP*dt)`，20ms时约0.077。`KI=0.5`只在重力方向基本一致时学习残余零偏，限幅±5°/s。正常转动由陀螺直接积分，不需要等待重力校正收敛。没有给最终角度再加额外低通。

标定通过加速度模长、轴向变化和陀螺变化筛选明显运动；缓慢匀速绕重力轴旋转可能通过这些检查，因此务必实际保持静止。标定只扣陀螺零偏，不会把加速度重力分量减掉，也不能补偿所有温漂或比例误差。

Yaw没有磁力计约束，仍会长期漂移，不能作为绝对航向；重力不能估计所有方向的零偏。输出基于芯片XYZ，安装时对照实物测试Pitch/Roll方向。

如果静止时Pitch/Roll仍持续大幅变化，先记录六轴原始值与实际时间间隔：静止加速度模长应约4096，陀螺各轴应稳定。初始化时的`gyro_bias[3]`可以在调试器查看。仅凭现象还不能排除传输误码、模块量程/器件异常或强振动。

当前Keil工程在主循环调用`MPU6500_ReadAngles`，不再使用此前的`Mahony_*`测试调用。不要混用两套姿态状态。
